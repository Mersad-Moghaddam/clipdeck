# ClipDeck v0.4 Design and Acceptance Contract

## Intent

Make retrieving an earlier clip immediate, understandable and trustworthy: verified install → capability check → copy synthetic items → open supported frontend → search → recognize preview → safely copy/paste the intended item.

## Goals

- Improve measured search/capture/render bottlenecks while preserving history and privacy.
- Keep the existing Omarchy HUD and shortcuts; fix category pagination, stale responses, cache lifetime and input/layout problems.
- Provide a CLI picker in compatible sessions, reusing daemon MIME-aware copy and optional injection.
- Release tested packages with truthful support diagnostics, then make targeted community submissions.

## Non-goals

- No universal desktop guarantee, fabricated benchmarks, fake stars, spam, telemetry or privileged injection by default.
- Native X11 capture, native GNOME/KDE extensions and a standalone rich QML app require separate scope/live tests; they are not v0.4 promises.
- No stack rewrite or sacrifice of history integrity/privacy for benchmark wins.

## Proposed Builder Decisions

These defaults follow the user's request to make the best choices; they are not independently confirmed platform guarantees.

- Keep Go/SQLite/Unix IPC and separate Quickshell plugin; respect current Go directive (1.27.2) and validate toolchain availability.
- Keep release binaries `CGO_ENABLED=0`; static compilation is not proof of desktop/protocol compatibility.
- Preserve history, pins, privacy controls, MIME fidelity and existing IPC clients; no destructive database rebuild during upgrade.
- Add explicit filtered `query`/`has_more` API, preserving legacy list/search totals and applying filters before paging.
- Portable picker defaults to copy-only; `--paste` requests injection. Preserve Omarchy Enter-paste behavior and existing shortcuts.
- No telemetry, clipboard-content logging, secret-bearing screenshots, paid promotion, fake stars, bulk spam or account creation without specific authorization.
- Bound subprocess execution/output; never invoke a shell with clipboard-derived arguments or automatically change privileged input-device permissions.
- Preserve masking, expiry and pause behavior across CLI, IPC, caches, reconnects and third-party selectors.
- Desktop support is per capability: capture, read, copy, paste injection, attribution, picker and Omarchy overlay. Never call untested combinations fully supported.

## Acceptance

- Correctness/upgrade tests preserve content/pins/blobs, literal search, international text and concurrent operation.
- Stretch: warm first-page store p95 ≤10 ms at 10k clips; minimum gate: ≥30% lower common-query median and no >10% reproducible regression in other query classes vs matched baseline.
- Target ≤100 ms p95 final-keystroke→rows and cached-open ≤100 ms p95 on recorded reference hardware; measure rendering instead of promising universal frame-time performance.
- Idle daemon RSS increase ≤10% unless a measured trade-off is approved; no rapid idle polling.
- Masked listings/menus by default; explicit consent for sensitive output; no secret logs/fixtures.
- Verify amd64 assets and arm64 native/emulated smoke tests, disclosing missing checks.
- Capability matrix records tested OS/compositor versions; clean install/upgrade/uninstall/checksum failure and rollback are tested before public promotion.
- Submission URLs and acceptance states are recorded separately; blocked accounts/platforms are never inferred successes.

## Experience Direction

Retain theme-native typography, surfaces and compact keyboard-first layout. Improve readable previews, hierarchy, focus, offline/loading feedback and first-run guidance before adding decoration. Preserve RTL/hover fixes, verify reduced motion, fractional scaling and IME composition. The portable picker is not the Omarchy HUD on all distros.

## Builder Discretion and Approval

Choose SQL indexes/PRAGMAs, cache sizes, debounce and package dependency changes from evidence; document trade-offs. Do not silently change search semantics, security boundaries or compatibility promises. The companion plan defines interfaces, tasks and verification. This review changes planning only; revised scope needs approval before implementation or publication.
