# ClipDeck v0.4: Performance, Desktop Experience, Distribution, and Launch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for inline execution, or superpowers:subagent-driven-development if delegation is approved. Steps use checkbox (`- [ ]`) syntax for tracking. This revision is a plan, not authorization to start implementation or publish.

**Goal:** Deliver a measurably faster, privacy-preserving ClipDeck with a polished Omarchy interface, a portable CLI picker, an honest desktop-support matrix, verified downloads, and targeted public discovery.

**Architecture:** Retain the Go daemon, SQLite FTS5 store, Unix-socket IPC, and separate Omarchy QML plugin. Optimize measured bottlenecks without changing search semantics accidentally; reuse daemon copy/paste operations rather than duplicating clipboard logic in the CLI. Detect desktop capabilities explicitly and publish only tested combinations, with readable fallback guidance for restricted environments.

**Tech Stack:** Existing `clipdeck/go.mod` toolchain/dependencies (currently `go 1.27.2`), pure-Go SQLite, Chroma, Quickshell/QML, shell packaging, GitHub Actions and nfpm. Do not advertise Go 1.21 support without validating the full dependency graph on that version.

**Spec:** `../specs/2026-10-17-clipdeck-v0.4-design.md`. Paths below are workspace-relative unless a command specifies its working directory.

## Global Constraints

- Preserve history, pins, privacy controls, MIME fidelity and existing IPC clients; no destructive database rebuild during upgrade.
- Keep release binaries `CGO_ENABLED=0`; static compilation is not proof of desktop/protocol compatibility.
- No telemetry, clipboard-content logging, secret-bearing screenshots, paid promotion, fake stars, bulk spam or account creation without specific authorization.
- Performance numbers are targets until reproduced; publish hardware, dataset, command, revision, sample count and warm/cold conditions with results.
- Desktop support is per capability: capture, read, copy, paste injection, attribution, picker and Omarchy overlay. Never call untested combinations fully supported.
- Bound subprocess execution/output; never invoke a shell with clipboard-derived arguments or automatically change privileged input-device permissions.
- Preserve masking, expiry and pause behavior across CLI, IPC, caches, reconnects and third-party selectors.
- Version `0.4.0` is provisional until checks pass. Push only exact intended tags, never all local tags; never overwrite published assets/tags.
- Workspace root is not a Git repository. Commit separately in `clipdeck/` and `omarchy-clipdeck/`; copy approved planning documents into `clipdeck/docs/superpowers/` before committing them.

## Review Focus

1. Search under concurrent capture/deletion: no deadlock, writer starvation, unstable paging or wrong selected item (Tasks 2–3, 7).
2. Secrets and menu/terminal injection: no raw sensitive content, control sequences, forged row parsing or stale-cache leakage (Tasks 4–5, 7).
3. Restricted Wayland protocols and hung tools: honest diagnostics, bounded completion and fallback without duplicate paste injection (Task 6).
4. Upgrade/install failure: preserve prior runnable binaries, service configuration and DB; checksums/migrations fail safely (Tasks 8–9).
5. UI races, layout and international input: stale responses cannot overwrite current results; focus, RTL, IME and fractional scaling remain usable (Task 7).

## Review Findings and Corrections

Source checks on 2026-10-17 establish this baseline; refresh it during execution:

- Earlier session runs of `go test ./...` and benchmarks passed. `BenchmarkSearch10000Items` reported **33.46 ms/op**; some common-query observations were **42–59 ms**. This is not a per-query p95 or a UI-open measurement.
- `clipdeck/internal/store/store.go` already has WAL, a pinned/updated index, trigram FTS and FTS-path `limit+1` paging. Fallback search performs an exact count; changing that silently changes its contract.
- `SearchItems` holds an `RLock` before calling `ListItems` for an empty query; `ListItems` also takes an `RLock`. Test pending-writer behavior and remove nested acquisition rather than assuming it is safe.
- `omarchy-clipdeck/overlay/ClipDeck.qml` already implements Alt+1..9, Ctrl+C, Ctrl+P, Delete and Ctrl+Enter variants. Preserve these instead of reimplementing them or calling nonexistent `togglePin`; existing deletion takes an item object.
- QML retrieves 200 items then filters categories locally; older matching clips can be omitted. Filters must be applied server-side before paging.
- Capture uses `wl-paste`; adding `xdotool`/`xclip` does not implement X11 capture. GNOME/KDE monitoring and virtual keyboard protocols require actual testing, not installation of a package.
- `handlePaste` copies, launches asynchronous injection, discards its error and returns success. Distinguish copied, injection requested and injection failed; command success is not proof of target-app delivery.
- `.github/workflows/release.yml` already builds amd64/arm64 tar/deb/rpm/apk on tags. Extend it rather than race it with a manual publisher.

Evidence: backend graph project `clipdeck`, generation `2026-10-17T08:05:54Z`, task-directed symbol searches/paste trace and source checks. Coverage check for backend evidence paths reported no recorded issue (best-effort, not proof of completeness). QML, workflows and packaging were read directly; the plugin was not graph-indexed for this review.

## Scope, Order and Acceptance

Deliver in four stages: **baseline/correctness → backend/CLI/UI → packaging/release → outreach**. Each task must be independently reviewable. Native X11 capture, GNOME/KDE extensions and a standalone rich QML app are deferred unless separately scoped, implemented and live-tested. The portable menu is not the Omarchy HUD on every distro.

| Area | Release criterion |
|---|---|
| Search correctness | Preserve literal/phrase semantics, escaping, filters and pin ordering; document intentional changes |
| Store performance | Stretch: warm first-page p95 ≤10 ms at 10k clips; minimum gate: ≥30% lower common-query median and no >10% reproducible regression in other classes vs matched baseline |
| End-to-end search | Target ≤100 ms p95 final keystroke→matching rows, including debounce/IPC/render on the recorded machine |
| UI | Target cached-open ≤100 ms p95; measure dropped frames at 60 Hz instead of promising universal sub-16 ms opens |
| Resources | Idle daemon RSS increase ≤10% vs matched baseline unless a measured trade-off is approved; no rapid polling when idle |
| Data/privacy | Upgrade/reopen preserves content/pins/blobs; listings/menus masked by default; explicit consent for sensitive output |
| Distribution | amd64 smoke tests; arm64 cross-build plus native/emulated smoke test, with unavailable validation disclosed |
| Compatibility | Capability matrix includes tested OS/compositor versions and evidence; no “works everywhere” claims |

Timing budgets belong in controlled benchmarks, not flaky millisecond unit-test assertions. A missed target is investigated/disclosed, never converted into a fabricated result.

### Task 2: Search Correctness and Concurrency Before Tuning

**Files:** `clipdeck/internal/store/{store.go,search_regression_test.go,search_bench_test.go}`.

**Interfaces:** Preserve `SearchItems(query string, limit, offset int) ([]Item, int, error)`. Dispatch empty queries before locking or extract lock-owned internals to avoid nested read locks.

- [ ] Add `TestSearchEmptyConcurrentWriter`, `TestSearchFilterCase`, `TestSearchLiteralEscapes`, `TestSearchUnicodeAndShortTerms`, `TestSearchStablePaging`, `TestSearchExpiredPolicy`, `TestSearchUpgradeReopen`. Assert exact result IDs/order, fixed-dataset page nonduplication, pinned order, quotes and `%`/`_`/backslash literals, mixed-case `TYPE:`/`APP:`, 1–2 rune fallback and Unicode. Pin expiry behavior before changing it.
- [ ] Use synchronization barriers and bounded deadlines for the pending-writer regression, with cleanup that cannot leave a hung goroutine; prove the test detects the nested-lock scenario rather than relying on scheduler luck.
- [ ] Run regressions independently before fixes. New-behavior tests must fail for the intended reason; preservation tests may initially pass.
- [ ] Fix observed defects only, retaining trigram literal/phrase semantics (not fuzzy search). Add/document a stable ordering tie-breaker where required.
- [ ] Add fixed-seed 10k/100k benchmarks: common/rare/no-match, short text, phrase, Unicode, punctuation, type/app/pinned filters, first/deep pages, large content and concurrent writes. Keep fixture setup outside timing and report allocations.
- [ ] Run store tests, store race tests and full suite; commit the correctness deliverable.

### Task 3: Measured Optimization and Additive Query Pagination

**Files:** Task 2 files; `clipdeck/internal/ipc/{server.go,query_test.go}`; backend protocol/performance docs.

**Interfaces:** Add `QueryOptions{Query string; Types []string; PinnedOnly bool; Limit int; Offset int}`, `QueryPage{Items []Item; HasMore bool}`, `Store.QueryItems(opts QueryOptions) (QueryPage, error)`. Add IPC `query` with `query`, `types`, `pinned_only`, `limit`, `offset` fields returning `{items,has_more}`. Preserve legacy list/search total semantics.

- [ ] Add `TestQueryFiltersBeforeLimit` with >200 newer off-category items and an older match; assert that match is returned. Add multiple-type, pinned+query, filter intersection, malformed/unknown-type, exact-boundary and empty-page tests. Defaults: limit 50, max 200, offset ≥0; invalid inputs produce invalid-params errors.
- [ ] Add `TestLegacySearchTotalsUnchanged`; run new tests and confirm missing API failures before implementation.
- [ ] Implement category/type filtering before pagination. Use `limit+1` for the new `HasMore` contract; do not silently replace exact legacy fallback totals. Intersect explicit and query-derived filters; conflicting valid filters return empty results.
- [ ] Capture `EXPLAIN QUERY PLAN`, CPU and allocation profiles. Investigate ranking/sorting, materializing full content, LIKE fallback and FTS joins; reordering predicates alone is not proof of optimization.
- [ ] Trial cache/mmap/temp-store settings, connection limits and indexes individually. Retain only measured wins without write/RSS regressions. Do not impose a 64 MB cache per connection blindly; indexes must match actual expressions, including `LOWER(type)` if retained.
- [ ] Compare five runs and per-query distributions on the same machine. Verify upgrade/reopen and concurrent capture/search; document rejected experiments too. A missed release performance gate blocks promotion pending diagnosis or accepted scope revision.
- [ ] Run full/race suites and matched benchmarks; update protocol examples and commit using measured claims.

### Task 4: Privacy and Existing Copy/Paste Contract

**Files:** Backend `internal/ipc/{server.go,hardening_test.go,query_test.go}`, `docs/PROTOCOL.md`.

**Interfaces:** Reuse existing copy/paste parameters and MIME handling. Add backward-compatible paste-status fields/events only after tests define their meaning.

- [ ] Add tests for sensitive list/query masking, full-item access policy, expired/deleted IDs, image and URI copy, plain/transformed copy, oversized payloads and clipboard command failure. No failed copy may bump history or report success.
- [ ] Audit reveal/get/export behavior. Menus/default JSON expose safe display fields, not hidden raw content, rich previews or paths. Document that trusted same-user clients can have access to full content; masking is not a security boundary against all local processes.

- [ ] Implement/test additive statuses and safe query serialization. Do not bypass daemon MIME, transform or privacy logic with CLI-specific clipboard writers.
- [ ] Run IPC/race tests, update protocol and commit.

### Task 5: Safe Portable CLI Picker and Listing

**Files:** `clipdeck/cmd/clipdeck/{main.go,history.go,history_test.go}`, backend README.

**Interfaces:** `runHistoryCommand(cfg *config.Config, args []string, stdout, stderr io.Writer) int`, dispatched by main. Commands: `list [--limit N] [--offset N] [--query Q] [--type T] [--json]`, `copy <id> [--plain]`, `pick [--tool fuzzel|wofi|rofi|dmenu|fzf] [--paste] [--query Q]`. Picker defaults to copy-only; Omarchy Enter behavior is unchanged. Daemon required: no silent offline DB creation.

- [ ] Write `TestHistoryCommandValidation`, `TestListMaskedJSON`, `TestPickerCancellation`, `TestPickerExactRowMapping`, `TestPickerSanitizesControls`, `TestPickerPreservesMIME`, `TestPickerMissingDaemon`. Cover duplicate/empty/multiline previews, tabs/ANSI, Unicode, forged menu output, deletion after selection, missing tools and explicit missing tool.
- [ ] Exit codes: 0 success/user cancel/empty history, 1 operational failure, 2 usage error. Diagnostics use stderr; JSON stdout remains parseable. For requested paste failure after successful copy, report partial success explicitly.
- [ ] Use fixed argv per picker, never `sh -c`. Keep numbered sanitized display rows→exact IDs in memory (native index output where available); reject unrecognized output. Never parse arbitrary preview text as an ID or send unmasked secrets to menu processes.
- [ ] Autodetect fuzzel→wofi→Wayland-capable rofi in supported Wayland sessions, rofi→dmenu on X11, fzf only with usable TTY. Respect explicit selection. Picker availability alone does not imply capture support.
- [ ] Implement through `query`/`copy`/optional `paste` IPC; preserve image/file MIME. User-interactive selectors have cancellation/reaping, not a short subprocess timeout.
- [ ] Run CLI/full tests and fake-executable integration tests with isolated PATH; document tool versions/keybindings/privacy and commit.

### Task 6: Desktop Capabilities, Bounded Tools and Capture Lifecycle

**Files:** Backend `internal/hypr/{hypr.go,hypr_test.go}`, `internal/capture/{capture.go,lifecycle_test.go}`, CLI doctor and compatibility doc.

**Interfaces:** Preserve `GetActiveWindow()`/`PasteDirectly()` wrappers; internal context-aware injectable runner. Overall attribution budget 250 ms; overall paste-injection budget 2 s. Installed tools and usable protocols are separate capability states.

- [ ] Fake-runner tests cover wrong-session tools, hangs/cancellation, malformed JSON, Sway floating-node traversal, unavailable app identity and injection permission denial. Tests must never type into the real desktop.
- [ ] Gate Hyprland/Sway probes by active session; use X11 tools only for X11. Missing attribution is normal, not a crash. Do not advertise Xwayland helpers as native Wayland support.
- [ ] Try only safe relevant injection tools; ydotool requires explicit configuration, daemon/permission guidance and no automatic privilege changes. A timed-out injection may already have delivered: do not retry another backend blindly and duplicate paste.
- [ ] Capture regressions cover owner exit, rapid updates, duplicate image/text notifications, pause/resume, password hints, oversized stream output, watcher restart and daemon cancellation. Bound reads before buffering; assert no payload logs and no leaked children/goroutines.
- [ ] Replace unconditional retry sleeps with context-aware waits; reset backoff after healthy operation. Finite clipboard/window reads have deadlines; watchers remain long-lived until cancellation. Preserve capture size limits and echo suppression tests.
- [ ] Extend doctor with session/protocol, clipboard/menu/injection and attribution results. Warn that unavailable attribution weakens app exclusion. Exclusion-dependent privacy settings fail closed unless the user explicitly accepts reduced protection; document/test that choice.
- [ ] Run full/race tests and synthetic live checks on available sessions. GNOME/KDE monitoring remains untested/unsupported until observed; record missing backend work rather than claiming support. Commit.

### Task 8: Installer Safety, Upgrade and Rollback

- [ ] Isolated HOME/PATH tests: latest/pinned versions, amd64/arm64, API/network failure, corrupt/checksum-mismatched archives, missing flag values, custom prefix, absent systemd, permission errors and failure during second-binary replacement.
- [ ] HTTPS download plus SHA256 verification before extraction; state checksum integrity is not independent publisher authentication. Resolve version once and validate archive paths/symlinks against traversal and unexpected entries.
- [ ] Stage/validate both binaries and retain prior versions. Use same-filesystem renames, restore both on partial replacement or health failure; two renames are not pairwise atomic.
- [ ] Preserve custom service/config files and detect working user service availability. Provide non-systemd foreground/autostart instructions. Root package hooks must not attempt to start arbitrary user sessions.
- [ ] Before incompatible migration, use SQLite-aware consistent backup (not a live WAL DB file copy). Test v0.3.1 upgrade and supported rollback on synthetic copied data; never delete history during uninstall without separate explicit purge.
- [ ] Run `bash -n packaging/install.sh`, shellcheck when available and `bash packaging/tests/install_test.sh`; verify dry-run has no install/service side effects. Commit.
